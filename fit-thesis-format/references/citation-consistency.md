# 引用一致性审核与学校规范修正

适用于本稿正文作者年份叙述、已有文献编号及其排版。只学习学院范本和范文的形式；所有例子均用作者、年份、编号占位，不迁入范文观点、数据、作者名单或参考文献。

## 要求来源与作者人数

学院范本的硬要求见`source-comments.json`批注36、72：完整方括号阿拉伯数字标号在所引内容末尾右上角；正文与文末条目准确对应；首次引用次序与文末序号一致；同篇多次引用使用同号。文末作者不超过三位全部列出，超过三位列前三名后加`,等`或`,et al.`，作者之间用英文逗号。

正文作者显示按2026-10-29使用者确认的学校要求执行以下目标。原范本未写明此人数阈值，不能据此否定本次确认，也不能把范文里的其他写法当作可选目标。

|人数|中文正文占位例|外文正文占位例|正文显示的判断|
|---|---|---|---|
|1位|`甲（YYYY）……[n]。`|`AuthorA（YYYY）……[n]。`|列唯一作者；不应无依据加“等”|
|2位|`甲和乙（YYYY）……[n]。`|`AuthorA和AuthorB（YYYY）……[n]。`|中英文都列两位作者，中间统一使用“和”|
|3位及以上|`甲等（YYYY）……[n]。`|`AuthorA et al.（YYYY）……[n]。`|中文首作者加“等”，英文首作者加“et al.”；不能用此规则截断文末恰三位的作者列表|

一位或两位作者，不能仅因为原文带“等”就推定有三人。文末前三名后带“等”只能说明超过三人，不能提供未列作者的真实姓名。外文姓名的姓氏、名字缩写、复姓、机构作者都不能仅按空格或大小写推断；审阅记录须给出核实后的作者信息和本稿目标显示。括号形式和年份文字沿用原文；本流程不修改文末作者名单、文献年份或题名。

## 排版范围

- 全文中的作者姓名、连接词、`等`/`et al.`、年份及年份括号都保持正文正常基线。作者年份被整段上标、年份下标、整句上标均需定位修正；不得顺带清除同段数学变量的合法上下标。
- 正文只给准确识别的完整`[n]`上标，左右括号和数字一起处理。跨run的标记须按完整字符范围处理，不能只抬高数字或因run边界漏掉一个括号。
- 使用可在Word手调的引用字符样式，设置上标、继承正文宋体/Times New Roman及12磅；不先硬改为约8磅再上标。
- 文末参考文献的`[n]`、作者、年份、页码及类型标识`[J]`、`[M]`等保持正常基线。文末条目应用学院参考文献段落样式：宋体/Times New Roman10.5磅、固定17磅、段前3磅、悬挂1字符。
- 标号放在已核实的被引内容末尾，学院范本示例在句号之前。若原编号位于年份后或另一处，先核实被引范围；学校标准模式可按范围记录规范位置，明确逐字不变模式则保留并报告。本流程的缺号补入须使用审核过的论述末尾位置。
- 公式中的`[n]`、数组、区间、图表统计单元、脚注尾注及修订文字不按文献标记猜测处理。OMML、MathType、域、书签、图片和已有数学上下标保持原对象及语义。

## 两种任务边界

**明确逐字不变模式**：逐字保留作者显示、年份、括号、连接词、等字、空格、标点、原引用编号、位置及文末全部文字。只处理确认角色内的字体、基线和完整引用上标；缺编号、错人数、编号对应不明等在外部报告。

**学校标准模式或单独引用规范化**：按学校要求修改论文已包含这类引用规范工作，不重复索要许可。允许的文字变化限于逐项审核记录中的正文作者显示缩略或人数一致性修正，以及补入准确绑定的已有文末条目的现有号码。每一条都须有可验证的来源绑定及精确字符范围白名单；不能将授权扩大为改写论述、改年份、补新文献、改文末条目、替换观点或重新编号全文。

研究内容保留不是声称所有XML文字完全不变。已授权的作者显示和新插入号码必须在前后差异记录中如实列出；白名单以外的正文、标题、表格、数据、论点、公式及文末参考文献仍须完全一致。作者简称变化也不能误删句子中的对象名称或共同作者之后的论述。

## 来源绑定与逐条审核

1. 从完整原始DOCX的副本开始，先读取原稿基线、段落定位和文末参考文献。扫描全文，区分正常叙述与真正的文献引用，列出缺数字标号、作者人数显示不一致、基线错误和疑似编号对应错误；不能只检查截图或文献综述前几段。
   已有数字标号的作者叙述也必须检查年份。`Vial……[5]`等缺少年份的写法列为`missing_year`待核验，不能因作者年份正则没有匹配而判为无问题。外文书目大写姓氏与正文正常大小写可作同一姓名的审核线索；同姓同年、同姓多篇及书目中的访问年份仍需逐项核对。只根据本稿已绑定条目的真实出版年份补入，不从作者知名度或外部印象猜年。
2. 对每条拟修正记录绑定本稿一个具体参考文献段落，核对段落定位、完整条目原文、既有编号、准确作者信息、文献年份以及对应论述。作者年份相同不足以证明是同一条；同年多个文献、同姓不同作者或共引多篇时须结合题名与已有上下文查证。
3. 明确正文作者显示范围、原年份及年份括号范围、被引论述范围、已有标记或缺号插入位置。目标作者显示来自经核实的作者列表；拟补号码只能来自已绑定条目的现有编号。记录原字符与目标字符，不用模糊关键词替换全文。
4. 只通过逐条审核的来源绑定记录执行。输入条目文字、作者年份或定位与审核记录不一致时拒绝该记录并报告，不能向邻近段落找一个“差不多”的匹配。没有文末条目时保留并报告缺来源；不联网拼造或复制范文条目。
5. 把每条允许变化作为精确范围白名单保存，检查拟改字符与论述、公式、域和其他作者叙述没有交叠。即使同段出现多次同一个作者年份，也必须分别定位，不能全局替换。

`narrative_citations.py`的初始范围仅为已经查证、没有复杂对象的正文直接子段落中的纯文字。表格、文本框、脚注尾注、修订、含域/书签/数学或绘图等复杂对象的位置保留并列为待定位审核；工具未支持不代表格式已合规，也不能删去这些对象以通过工具。全文检查范围与自动修正范围必须分别报告。

## 工具操作与验证

工具分为`inspect`、`apply`、`verify`三步。先读取检查清单，再根据真实段落文字逐项准备来源绑定记录；不能根据截图估算偏移。下面的`SOURCE.docx`、`NEW.docx`和JSON文件名均为命令占位，执行时替换为实际原稿、输出及记录路径。

```text
python scripts/narrative_citations.py inspect SOURCE.docx --out INVENTORY.json
python scripts/narrative_citations.py apply --source SOURCE.docx --output NEW.docx --map REVIEWED.json --report APPLY.json
python scripts/narrative_citations.py verify --source SOURCE.docx --output NEW.docx --map REVIEWED.json --report VERIFY.json
```

`inspect`读取完整输入并列出参考文献及正文候选，不等于查证作者和论述来源。审核后再把明确的来源绑定记录传给`apply`，输出到新文件；保留原稿、记录文件及每条成功/拒绝结果。

审核映射的顶层为`schema_version=1`、`reviewed=true`、`source_sha256`及`records`。`reviewed`表示记录已完成逐项审核，不是允许绕过来源核实的开关；`source_sha256`必须对应当前完整输入文件。每条记录的字段如下，字符串均取自当前输入，不复制占位例：

|字段|绑定内容|
|---|---|
|`pid`|正文目标段落定位|
|`author_year`|作者年份整体的`start/end/expected_text`；内含`author`与`year`各自的`start/end/expected_text`|
|`claim`|被引论述的`start/end/expected_text`，缺号补入的末端应在句末标点之前，不能包含该标点|
|`reference`|具体文末段落的`pid/expected_text/reference_number`；内含`author_list`及`year`的`start/end/expected_text`|
|`reference.authors`|逐名核实的`start/end/exact_name/display_name/language`，`language`为`zh`或`en`；精确姓名来自条目，显示姓名须有核实依据|
|`connector`|仅两位作者使用，中英文目标都必须为`和`；来源原有其他连接词可识别并修正|
|`abbreviation`|仅三位及以上使用；中文目标必须为`等`，英文目标必须为`et al.`，不能给单人或双人套多人标记|

所有正文嵌套范围仍是**正文段落中的绝对字符偏移**；`reference`内部范围是**参考文献段落中的绝对字符偏移**，不是相对`author_year`或`author_list`的局部偏移。范围与`expected_text`必须同时准确，不用手算猜测替代工具清单和逐字定位。

文末前三位后有“等”或“et al.”的条目可识别为超过三位；该后缀不是姓名，也不能据此猜出其余作者。只绑定条目实际列出的已查证姓名；不能为了凑一个完整作者数组删改文末条目或编造姓名。原有同一论述末尾`[n]`准确对应时保留其文字，只调整完整上标；缺号时只在审核过的`claim.end`补入绑定条目的现有号码。作者年份相符但已有标号冲突、引用范围不明或复合标号无法准确绑定时保留并报告。同作者同年多篇在扫描阶段保持歧义；只有人工依据题名与论述明确选定现有条目，并在正式记录绑定其精确PID、全文和编号后才可继续，不能自动猜选。

既有句号后的编号、数字方括号内带空格或全角方括号，工具会保留并要求人工复核，不能把它们当成“缺号”再补一次。年份后已有准确号码可保留原位置；新补号码须审核完整被引论述，年份后仍有论述时不能只选择作者年份片段就插入。没有可识别的参考文献标题或参考文献段落样式时，独立数字开头段落不自动证明是书目来源。外文姓名内部子串不作为作者绑定证据。

`verify`必须用原稿、输出稿和同一份审核记录核验实际变化：每处作者显示与补号都在白名单内，条目绑定与原文仍一致，论述、数据及文末条目逐字未变，完整`[n]`上标而作者年份基线正确。工具输出成功只能说明它支持的范围通过，不能代替全文审核或实际渲染。

完成后还要检查：首次引用次序是否与现有文末编号冲突，同篇是否同号，文末是否仍有未引用条目，有无正文标号找不到条目。发现冲突报告定位，不在本范围内静默重排参考文献或全文号码。复合标号、连续序号及具体页码后缀按模板另行审核，不把`[3,5]`、`[8]10-11`等随意拆开或合并。

交付前实际查看Word/PDF中的修改段落、跨行位置及参考文献页，确认两个括号都上标、标号位于核实的论述末尾、作者年份和句读保持基线，且没有数学对象受损。交付说明区分全文审核结果、已自动修正项、复杂位置待审核项及实际完成的结构/渲染检查。
